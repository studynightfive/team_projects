# 2026-07-27 商品运营看板变更记录

## 1. 变更目的

管理看板原先按完整问题文本统计“高频问题”，同一商品的不同问法会被拆开。本次把统计中心调整为商品实体，使看板能反映商品查询热度、商品匹配情况和资料建设质量。

## 2. 主要修改

- RAG 检索完成后，以最终第一条引用文档作为本次问答的主商品。
- `retrieval_metrics` 增加主商品标识和名称快照，不保存用户问题或答案正文。
- 管理看板新增商品查询量和商品匹配率。
- “高频问题”替换为“热门商品”，按商品文档标识聚合查询次数。
- 前端文案调整为商品查询、商品资料处理、门店位置补充和商品检索评测口径。
- OpenAPI、生成的 TypeScript 类型、Mock 和测试同步更新。

## 3. 数据库迁移

部署新版本时执行：

```powershell
docker compose --env-file deploy/env/.env -f deploy/docker-compose.yml run --rm migrate
```

迁移版本为 `0023_metric_product_entity`。历史检索指标不会按问题文本猜测商品，升级后的新问答开始形成商品热度。

## 4. 运营口径

- 商品查询量只统计完成的 RAG 回答请求。
- 商品匹配率为有最终引用的有效回答数除以商品查询量。
- 热门商品只统计有最终引用的回答；无引用回答不进入商品排行。
- 同一商品的不同问法只要最终第一引用的文档 ID 相同，就合并计数。
- 当前推荐一件商品对应一份文档，文档正文同时维护商品详情和店铺位置信息。

## 6. 剩余限制

平台目前没有独立商品主数据表。若一份文档混合多个商品，主商品只能按最终第一引用文档识别；后续需要更细粒度分析时，应增加商品、店铺及文档映射表。
