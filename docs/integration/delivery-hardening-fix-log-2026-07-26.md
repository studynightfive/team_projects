# 交付加固修正记录

## 1. 修正范围

本轮围绕真实 RAG、评测可信度、角色边界、业务看板和 Linux 交付保护进行核查。
修改遵循现有 FastAPI、Vue 3、PostgreSQL、pgvector、Redis 和 Worker 架构，没有新增
第二套业务接口或替换组员已有模块。

## 2. 主要修正

## 3. 角色和数据边界

- 普通用户：可见本人个人知识库和本部门企业知识库；不能看到其他部门知识库，也不能
  进入管理中心或上传企业文档。
- 知识库编辑者：继承普通用户能力，并可创建、上传、重处理、删除和恢复本部门企业
  知识库文档。
- 超级管理员：可进入完整管理中心，管理用户、部门、模型、知识库、文档和检索评测。
- 测试集、运行记录、知识库列表、检索请求和文档接口均由后端执行最终权限校验，前端
  隐藏按钮不作为安全边界。

## 4. RAG 正确性与速度

当前链路为：文档转 Markdown 与清洗 -> 按上传时策略切分 -> Embedding 入库 ->
关键词/向量混合召回 -> Rerank -> 引用上下文与会话上下文 -> 聊天模型生成答案。

准确性由以下机制共同约束：

1. RAG 默认使用混合检索和真实重排。
2. 对外相关性分数与阈值判断采用同一口径。
3. 系统提示词要求逐项引用、禁止脱离资料补全事实，并显式处理资料冲突。
4. 命中率测试使用人工标注的相关 chunk 计算 Hit Rate、MRR、Recall 和 MAP。
5. 文档或模型变化后通过批量重处理重新生成向量，缓存作用域包含知识版本和模型版本。

检索命中率只能说明相关片段是否被召回，不等于生成答案绝对正确。业务看板因此使用
“评测命中率”名称，不将“存在引用”冒充为正确率。要持续保障回答质量，应维护覆盖真实
业务问题的标注测试集，并对答案事实一致性增加人工抽检。

真实浏览器联调中，首次外部模型问答约 15 秒；高相似改写命中语义缓存约 2 秒。实际
速度仍受外部 Embedding、Rerank 和聊天模型网络延迟影响。

## 5. 验证结果

- 前端：TypeScript、ESLint、Vitest 和生产构建通过，共 `120` 个测试通过。
- 后端：Alembic 升级与检查、Ruff、Mypy 和 Pytest 通过，共 `445` 个测试通过、
  `2` 个跳过；覆盖率 `66.36%`，高于项目 `50%` 门禁。
- 样例验收：`45` 项通过、`0` 项失败、`20` 项待制作。
- 真实 UI：验证 1440px、1280px、375px 无页面级横向溢出。
- 真实角色：普通用户仅看到个人库和医疗部门库；知识库编辑者可联合选择医疗库与
  个人库；普通用户无管理入口和企业文档上传入口。
- 真实评测：同一问题在阈值 `0.30` 时命中，最高候选分数 `0.65`；阈值 `0.70`
  时未命中，证明阈值真实参与判断。
- 原生镜像：API 与 Worker 可以导入受保护 `.so`，运行镜像中对应 `.py/.pyx`
  不存在。

## 6. 已知限制

- OCR 流水线和运行依赖已接入，但样例库仍有图片、复杂表格等验收素材待补充，不能把
  “代码存在”当作所有版式识别质量都已验证。
- 浏览器原生保存位置选择器属于操作系统窗口，自动化测试只能验证格式选择与下载接口，
  无法替用户确认具体磁盘目录。
- Cython 是源码交付加固而非绝对防逆向；生产仍须限制镜像仓库权限、使用签名许可证和
  云 Secret，并在构建时注入 Ed25519 公钥。
- 生产启用许可证校验前，需要由独立签发环境生成许可证并挂载到容器；私钥不得进入本
  仓库、镜像、环境示例或日志。
