# 工作流一致性修复技术方案

## 1. 目标

本次修复 Issue #61 的五条用户链路：

1. 从“我的空间”发起提问时，必须等待真实知识库与聊天模型加载完成，再执行一次搜索。
2. “我的下载”中的问答结果可选择 Markdown、Word 或 PDF 重新生成并下载。
3. 新增模型时，根据供应商与用途展示常用模型标识，同时允许管理员输入其他标识。
4. 管理端文档列表使用当前页面内的真实预览抽屉，不跳转到用户工作区。
5. AI 问答页按“问题与答案在上、输入框在下”组织；流式回答增长时自动跟随最新内容。

## 2. 关键约束

- 搜索初始化分为“读取导航意图”和“加载真实选项”两个阶段。只有二者都完成后才允许自动搜索，
  防止把前端占位模型标识作为真实模型 ID 提交。
- 导出转换只允许当前用户自己的、已完成且未过期的问答任务。服务端从任务目录中的受控
  Markdown 源文件生成新格式，不接受客户端传回历史答案正文。
- 新问答导出同时保存不可公开下载的规范 Markdown 源文件。历史 Markdown 任务可直接作为
  兼容源；缺少规范源的历史 PDF/Word 任务明确提示重新导出，不做不可靠的逆向解析。
- 模型建议是输入辅助，不是白名单。最终模型标识仍以管理员输入和供应商真实开通范围为准。
- 管理端预览继续调用现有鉴权文档接口，支持原文、Markdown 和分页分块，不拼接静态存储路径。
- 自动滚动只在新搜索开始和用户仍接近页面底部时生效；用户主动向上阅读后不强制抢回滚动位置。

## 3. API 变更

### `POST /api/v1/exports/{export_id}/convert`

请求：

```json
{
  "format": "docx"
}
```

其中 `format` 仅允许 `markdown`、`docx`、`pdf`。

成功响应直接返回文件，并通过 `X-Export-Id` 返回新导出记录 ID。新记录会出现在“我的下载”。

错误边界：

- 非本人任务或任务不存在：`404`
- 非问答任务、未完成或已过期：`409`
- 历史任务没有可转换 Markdown 源：`409`
- 文件生成失败：`500`，同时保留失败任务记录

- 组件测试覆盖空间导航自动搜索只执行一次，且使用加载后的真实模型 ID。
- 后端测试覆盖问答源文件保存、Markdown 转 Word/PDF、新任务记录与权限边界。
- 前端测试覆盖下载格式选择、模型建议及自定义输入、管理端原地预览、底部输入框与自动跟随。
- 运行 TypeScript、ESLint、Vitest、Ruff、Mypy、Pytest、OpenAPI 类型生成和生产构建。
- Docker 重建后检查 1440px、1280px、375px 页面，无根级横向溢出和控制台错误。
