# 会话式 AI 搜索需求说明

## 1. 背景

当前 AI 搜索一次只展示一个问题与答案，真实 RAG 接口不会保存搜索过程，也不会把上一轮问答作为下一轮问题的上下文。“我的空间”会自动填充并提交固定问题，“收藏内容”则与用户需要回看的问答历史不一致。

## 2. 目标

1. 从“我的空间”点击“向空间提问”后，只打开 AI 搜索并选中对应知识库。
2. 提交问题后立即清空输入框，问题和流式答案保留在当前页面。
3. 一个会话内可以连续提问，后续答案结合当前会话历史和最新检索片段生成。
4. 点击“新建对话”后清空当前消息，但保留知识库和模型选择；已有消息已经实时保存，无需再次确认。
5. 将“收藏内容”入口替换为“对话历史”，支持分页、搜索、查看、继续和删除本人会话。
6. 用户工作区根路径直接展示会话式 AI 搜索，不再先展示高频任务、知识共建等首页卡片，也不再跳转到另一搜索结果页。
7. 搜索页采用紧凑的单页对话布局：历史问题和答案位于同一内容流，输入框固定在底部；引用与原始结果作为回答的可核验信息保留。
8. 没有外部预选范围时，默认选择第一份包含已处理文档的可访问知识库，避免空个人知识库导致所有问题均无引用。

## 3. 验收标准

- “我的空间”跳转后输入框为空、未发起检索、目标知识库已选中。
- 提交后输入框为空；同页能看到至少两轮用户问题和对应答案。
- 第二轮请求携带首轮返回的会话 ID，后端生成提示词包含历史消息。
- 刷新带有会话 ID 的搜索页后可以恢复该会话的消息和知识库范围。
- 新建对话不会删除旧会话，旧会话能在“对话历史”中分页查询和打开。
- 用户不能读取、续写或删除其他用户的会话。
- 多知识库会话的范围在创建后保持固定；更换范围需新建对话。
- 首轮仍保留语义缓存、混合检索和重排；追问不误用其他上下文的答案缓存。
- `/` 直接承载搜索输入和问答结果，提交问题只更新当前页面，不发生组件级页面跳转。
- `/search` 兼容旧链接，并重定向到 `/`；会话 ID 可继续通过查询参数恢复。
- 搜索页不显示“知识共建”“高频任务”“辅助信息”侧栏和独立查询摘要条。
- 默认知识库必须优先选择 `ready_document_count > 0` 的范围；仅在所有可访问知识库均为空时才回退到首项。

## 4. 非目标

- 不实现多人共享会话、会话分支、消息编辑和回答重新生成。
- 不删除后端收藏接口及历史收藏数据，只从用户主导航移除收藏页面。
- 不展示模型隐藏推理过程。

## 5. 风险与约束

- 长会话会增加模型输入长度，因此只注入最近消息，并受字符预算限制。
- 流式请求中途失败时也必须保存已提交的问题和明确的失败状态，不能产生不可见的“幽灵会话”。
- 会话知识库范围必须由后端校验，前端锁定选择仅用于改善体验，不能替代权限控制。
