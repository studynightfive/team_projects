# 检索与上传工作流代码审计记录

## 1. 审计范围

本次审计围绕 Issue #59 的四条交付链路，不扩展无关模块：

1. 文档上传、重处理和导出任务的状态刷新；
2. RAG 精确缓存与语义相似缓存；
3. AI 搜索的多知识库范围；
4. 同一知识库内的文档名称唯一与冲突处理。

## 2. 多知识库检索

### 请求流向

1. `AiSearchBox.vue` 维护已选知识库 ID，并在提交前校验数量、有效 ID 和规范化名称。
2. `ai-search-real.ts` 将前端 `workspaceIds` 转为 OpenAPI 字段 `kb_ids`。
3. `SearchRequest` 拒绝同时提交 `kb_id` 与 `kb_ids`，并拒绝重复 ID。
4. `_resolve_knowledge_base_scope()` 在读取答案缓存和执行真实检索前，统一校验权限与同名知识库。
5. `search()` 只把校验后的 ID 集合传给关键词、向量、重排和结果后置权限过滤。

### 关键设计

- 前端隐藏或禁用选项只是交互保护，服务端仍逐次校验权限。
- 无权知识库返回空范围，不区分“不存在”和“无权限”，避免跨部门数据探测。
- 缓存作用域使用排序后的知识库 ID 集合，因此选择顺序不同不会产生两份等价缓存。

## 3. 语义答案缓存

### 命中顺序

1. 使用标准化问题读取精确缓存，不调用 Embedding；
2. 精确未命中时生成一次查询向量；
3. 在同一用户、知识库版本、模型和检索参数作用域内读取最近候选；
4. 先校验问题类型、否定关系、数字和英文实体，再计算余弦相似度；
5. 相似度不低于 `0.95` 才复用答案；
6. 未命中时把同一查询向量继续交给向量或混合检索，避免重复调用模型。

### 降级行为

- Redis 不可用：视为缓存未命中，继续正常 RAG；
- Embedding 不可用：保留精确缓存，混合检索按既有逻辑回退关键词；
- 旧缓存没有查询向量：只参与精确匹配；
- 取消、失败或没有引用的回答：不写入缓存。

## 4. 文档名称冲突

### 上传流向

1. 浏览器把多个文件保留在内存队列，用户确认前不上传；
2. `name-conflicts` 接口使用与真实上传相同的文件名清洗和名称规范化规则；
3. 无冲突时前端使用严格的 `new_version` 策略提交；
4. 有冲突时用户明确选择 `replace` 或 `rename`；
5. 服务层再次检查名称，数据库部分唯一索引处理并发竞争。

### 策略语义

- `new_version`：名称被占用时返回 409，不静默处理；
- `replace`：替换唯一的同名文档，并递增 `document.version`；
- `rename`：生成 `名称 (2)`、`名称 (3)` 等可读标识；
- 同一批文件自身重名：禁止 `replace`，因为无法确定哪一份是最终替换内容。

活动文档的数据库约束为：

```text
(knowledge_base_id, lower(trim(title))) WHERE deleted_at IS NULL
```

软删除文档不占用名称；恢复时如果名称已被使用，自动添加编号并重新处理。

## 5. 任务进度

### 后端

- 非内联 Worker 在进入运行态和每个处理阶段后提交状态；
- 新索引全部生成成功后才切换为活动代次；
- Worker 最终提交成功、失败、取消或人工处理状态；
- 导出 Worker 在开始和每个文档完成后提交进度。

### 前端

- 只要存在排队或运行任务，每秒串行轮询一次；
- 每轮请求绑定轮询代次，旧请求不能覆盖新任务集合；
- 页面卸载会递增代次、中止请求并清除定时器；
- 上传已成功但首次任务详情查询失败时，先显示“排队中”占位状态，再由轮询恢复；
- 全部任务进入终态后停止请求。

## 6. 本次发现并修复的问题

| 问题 | 风险 | 修复 |
| --- | --- | --- |
| 同名知识库校验晚于缓存读取 | 极端情况下可能先返回旧缓存 | 缓存与检索共用范围解析器 |
| 中止的轮询请求仍会重新设置定时器 | 切页后继续请求、状态互相覆盖 | 增加组件存活标记和轮询代次 |
| 无冲突预检后默认自动改名 | 并发冲突绕过用户确认 | 默认改为 `new_version`，冲突返回 409 |
| 批内重名允许点击替换 | 多个任务反复覆盖同一文档 | 前后端同时禁止批内重名替换 |
| 替换文档未写回版本号 | 缓存版本语义不完整，可能撞哈希版本约束 | 替换时版本递增并写回 |
| 上传成功后任务详情查询失败会误报整批失败 | 用户重试可能制造重复上传 | 使用排队占位状态并交给轮询恢复 |
