# 知识库归档生命周期技术说明

## 1. 目标

知识库归档是可恢复的只读下架操作，不删除知识库、原始文档、Markdown、分块或向量。
恢复后沿用归档前的数据和索引重新开放。

## 2. 行为边界

| 场景 | 启用知识库 | 归档知识库 |
| --- | --- | --- |
| 管理端知识库清单 | 显示 | 显示，可恢复 |
| 普通用户知识库和空间清单 | 显示 | 隐藏 |
| AI 搜索知识库选项 | 显示 | 隐藏 |
| 管理端查看文档 | 允许 | 允许，只读 |
| 上传、重处理、删除、恢复文档 | 允许 | 拒绝 |
| RAG 检索、流式问答、继续历史会话 | 允许 | 拒绝 |

管理端仍使用 `/api/v1/knowledge-bases` 获取全部有权管理的知识库；用户工作区、检索范围和
测试集知识库选择统一使用 `/api/v1/knowledge-bases/available`，该接口只返回 `active` 状态。

## 3. 后端约束

1. RAG 可访问知识库 ID 的 SQL 必须包含 `KnowledgeBase.status == "active"`，缓存读取前也必须
   完成该校验，防止历史缓存或继续会话绕过归档状态。
2. 客户端明确指定不可用知识库或当前没有可检索知识库时，返回不泄露资源存在性的统一校验错误。
3. 文档上传、同名预检、重新处理、删除和恢复在服务层统一检查知识库为启用状态；前端隐藏按钮不能
   代替后端校验。
4. 管理端文档列表返回 `knowledge_base_status`，用于把归档知识库文档呈现为只读。

## 4. 前端约束

1. 用户首页、企业知识库、我的空间、知识库详情、AI 搜索和命中率测试选择器只读取可用知识库。
2. 管理端知识库清单对归档项隐藏上传入口，只保留编辑和恢复。
3. 管理端文档清单允许查看归档知识库文档，但不能勾选或执行重新处理、删除、恢复操作。

## 5. 验收与验证

- 单元测试覆盖 RAG 权限集合排除归档库、显式选择归档库被拒绝。
- 文档服务测试覆盖归档库上传、重处理和批量写操作被拒绝。
- 前端服务测试确认可用知识库调用真实 `/v1/knowledge-bases/available`。
- 页面测试确认用户搜索不包含归档库，管理端归档项无上传和文档写操作。
- 运行后端 Ruff、Mypy、相关 Pytest，以及前端类型检查、ESLint、Vitest 和生产构建。
