# 云端验收缺口修正 PRD

## 背景

云端测试暴露出 RAG 预处理与观测未真正接入、文档操作反馈不及时、导出命名不可控、
部门看板口径混淆等问题。本次只补齐既有功能链路，不改变权限模型、部署拓扑或知识库
数据结构。

## 目标

1. 用户问题在检索前完成语义安全判定和检索改写；同义问法可以提高召回，并可命中高
   置信度语义答案缓存。
2. RAG 的预处理、缓存、检索、重排和生成阶段可选上报 Langfuse；未配置时不影响问答。
3. 删除文档成功后列表立即更新，随后只做一次静默校准，不出现重复加载和页面闪烁。
4. 重新处理文档时可重新选择切分方法、大小和重叠字符，并重建 Markdown、分块和向量。
5. 问答导出时可输入文件名，服务端负责清理路径字符并保留正确扩展名。
6. 超级管理员切换部门后，全部业务指标只统计响应中 `scope.department_id` 对应部门；部门
   管理员始终只能查看本部门。
7. 输入限制不仅检查关键词，还能识别规避关键词的涉黄、涉赌、涉毒意图；合法的医疗、
   法律、治理和科普问题应放行。

## 验收标准

- 三种近义问法能产生稳定的检索主查询；第二次高相似问答在同一权限、文档版本和模型
  作用域内可显示“相似问题缓存命中”。
- 语义预检采用防抖和服务端短期缓存；用户点击后立即复用或完成当前检查，合规时自动
  提交，违规时按钮不可提交且显示统一提示，避免二次点击和结果页报错。
- Langfuse 配置完整时能看到一条 RAG trace 及阶段 observations；关闭或故障时问答继续。
- 一次删除 1 个或多个文档后，当前列表立即移除，回收站可见且 30 天内可恢复。
- 单个和批量重新处理请求都携带切分配置，任务进度可见，完成后文档保存新配置。
- PDF、Word、Markdown 导出均支持用户命名；`../`、斜杠和控制字符不能进入存储路径。
- 部门 A/B 各有独立数据时，切换范围后总量、检索指标、热门商品、评测和贡献榜均隔离。
- 关键词规则、语义模型失败、超时和正常问题均有测试；模型失败按配置降级，不泄露正文
  到日志。

## 非目标

- 不恢复已撤销的本地 `llm-guard`、PyTorch 或大体积 BanTopics 模型。
- 不改变“缓存仅在权限、知识版本、模型和检索参数一致时复用”的安全边界。
- 不展示模型私有思考过程，不把用户问题或答案默认写入观测平台。
